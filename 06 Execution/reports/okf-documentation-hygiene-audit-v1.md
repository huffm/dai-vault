# OKF Documentation Hygiene Audit v1 -- Evidence Report

## purpose

Audit DAI vault docs for OKF consistency during the overnight settlement-finality wait, with priority on the docs
active in the current workflow. Record what is already compliant, what (if anything) needs normalizing now, and what
is deliberately deferred -- then ship a review/study guide alongside. This is a **docs-only hygiene slice**, not a
code, generation, reconciliation, or calibration slice.

## scope audited

- **`06 Execution/` -- fully enumerated.** All 69 non-archive `.md` files checked for a leading `---` front-matter
  block; the seven current-workflow priority docs read in full.
- **Priority current-workflow docs (read in full):** the registry-routed v8 backed-depth cohort, paid registry
  routing canary v1, registry-authoritative routing canary v2, source-readiness preflight gate v1, prompt route
  attribution contract v1, canonical reconciliation residue contract v1, and the v8 canary-halt v2.
- **Rest of vault (`02 Platform`, `03 Niches`, `04 Products`, `05 Research`) -- sampled / out of scope.** Not
  exhaustively enumerated this slice; they are not part of the active runtime workflow and the OKF taxonomy is
  scoped to `06 Execution`. Left for a future pass if a real retrieval problem appears.

Honest framing: **current active docs audited and confirmed; `06 Execution` fully enumerated; the wider vault
sampled, not certified.** No claim of full-vault perfection.

## headline finding

**The active workflow is already OKF-compliant.** Every one of the seven priority docs was *born* in
`reconciliations/` with complete, consistent 9-field front matter and `type == folder`. No priority doc required
normalization. This is the migration closeout working as designed: OKF is in opportunistic maintenance, new docs are
born correct, and no backfill was needed.

Within `06 Execution`: **55 of 69** non-archive docs carry front matter. The **14** that do not are *exactly* the
intentionally-flat categories the [[okf-migration-closeout-v1]] named as out of OKF scope (rolling logs, backlogs,
roadmaps, the next-slice proposal, launch checklists, skills inventories, and the untracked state snapshot). In
other words, **100% of the docs that are supposed to carry OKF front matter do.** There is no compliance gap to
close, so no doc was retrofitted -- retrofitting would be churn against a closed thread.

## docs normalized

**None retrofitted.** The active docs were already compliant, so normalization would have been churn. Two docs were
**created** (born compliant): this audit report and the [[okf-documentation-review-guide-v1]].

## docs deferred

All 14 non-front-mattered `06 Execution` docs are deferred **by the standing rule, not by neglect** -- they belong
to the intentionally-flat categories (rolling logs, backlogs, roadmaps, proposals, checklists, skills inventories,
state snapshot). The wider vault (`02`-`05`) is deferred as out of the current active-workflow scope. None of these
present a retrieval problem today.

## common issues found

- **No compliance gap in the active surface.** The main "issue" is the absence of one: the born-correct rule is
  holding, so there was nothing to fix.
- **One stale proposal.** `prompting/next-slice.md` is from 2026-06-24 and points at a since-superseded slice. It is
  intentionally flat and is regenerated by slice tooling, so it was **not** hand-edited here; flagged only.
- **Schema-fork risk (pre-empted).** The slice brief suggested a generic OKF front-matter shape
  (`id`/`created`/`updated`/`area`/`draft|active|...`) that differs from DAI's settled 9-field schema. Adopting it
  would fork the vocabulary. The new guide documents DAI's canonical schema and explicitly rules the fork out.

## whether any files were moved

**No files moved.** No `git mv`. The two new docs were born directly in their correct `type` folders
(`patterns/` for the execution-pattern guide, `reports/` for this evidence-report), so `type == folder` holds with
no relocation. No old doc was found current, touched, and misplaced, so no move was warranted.

## recommended future cleanup (non-blocking)

- **Wider-vault OKF pass**, *only if* a retrieval problem surfaces in `02`-`05`. Not warranted preemptively.
- **`next-slice.md` regeneration** happens through the slice-prompt tooling when the next runtime slice is derived;
  no manual action here.
- **Optional tiny validator** (deferred idea from the pattern doc): a read-only check that front matter is valid
  YAML with the nine fields and `type == folder`. Worth it only if the vault grows enough to drift.
